# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A native SwiftUI todo app (iOS + macOS from one codebase) that ranks tasks using Weighted Shortest
Processing Time (WSPT): `priority = importance / (2 × estimated_minutes)`, sorted descending, ties
broken by `createdAt` ascending (oldest first). Done items always sink below open items.

`docs/overvall-plan.md` is the original design doc; `python-logic/python-logic.py` is a Python
reference prototype of the sort; `docs/wspt-todo.html` is a working HTML/JS prototype whose UX (add
form, score-badge rows, done/delete actions, empty state) the SwiftUI views mirror line-for-line —
consult it when a view's exact layout/behavior is ambiguous.

v1 scope is intentionally pure WSPT only — no aging/starvation logic and no CloudKit sync. Both are
explicit v2 items; the domain model and persistence model are already shaped so they can be added
without a rework (see "Design constraints to preserve" below).

## Repository layout

Two separate Swift packages/projects, kept deliberately decoupled:

- **`WSPTCore/`** — a standalone Swift Package (no UIKit/AppKit/SwiftUI/SwiftData dependency)
  containing all WSPT domain logic: `Importance` (1–5 enum), `TodoItem` (pure struct), and
  `PriorityScorer` (scoring + ranking). This is the unit-tested core.
- **`WSPTTodo/`** — the Xcode project (generated by XcodeGen, see below) that depends on `WSPTCore`
  as a local Swift package. Contains the SwiftData persistence model (`TodoItemModel`) and all
  SwiftUI views. Builds two targets from one source set: `WSPTTodo_iOS` and `WSPTTodo_macOS`.

The Xcode project file is **generated, not hand-edited**: `WSPTTodo/project.yml` is the source of
truth (XcodeGen spec); `WSPTTodo/WSPTTodo.xcodeproj` and `WSPTTodo/Generated/Info.plist` are
generated output that happens to be committed. Edit `project.yml` and targets/settings/sources
changes, then regenerate — do not edit `project.pbxproj` by hand.

## Commands

### WSPTCore (domain logic package)

```sh
cd WSPTCore
swift build
swift test                                  # run all tests
swift test --filter PriorityScorerTests     # run one test suite
```

### WSPTTodo (the app)

Regenerate the Xcode project after changing `project.yml` or adding/removing source files:

```sh
cd WSPTTodo
xcodegen generate
```

Build each platform target via CLI (no Xcode GUI required):

```sh
cd WSPTTodo
xcodebuild build -project WSPTTodo.xcodeproj -scheme WSPTTodo_iOS   -destination 'generic/platform=iOS Simulator'
xcodebuild build -project WSPTTodo.xcodeproj -scheme WSPTTodo_macOS -destination 'platform=macOS'
```

List available schemes/targets with `xcodebuild -list -project WSPTTodo.xcodeproj`.

To run/verify visually in Simulator: `xcrun simctl` install/launch/screenshot against the built
`.app` (see build output path under `DerivedData`). Note `screencapture -x` for the macOS app
window may fail in sandboxed shells due to Screen Recording permissions — verifying the process is
running (`pgrep -fl`) is an acceptable fallback since both platforms share identical SwiftUI view
code.

### Python reference prototype

`python-logic/python-logic.py` and `python-logic/tester.ipynb` are reference-only, not part of the
shipped app. A `.venv` exists for running the notebook if needed; it is not part of the build.

## Architecture

**Domain/persistence split.** `WSPTCore.TodoItem` (pure struct) and `TodoItemModel` (`@Model`,
SwiftData) are deliberately two separate types, not one `@Model` conforming to a shared protocol.
`TodoItemModel.asTodoItem` maps to the pure struct for scoring. This keeps `PriorityScorer`
framework-free and unit-testable in `WSPTCore`, and keeps persistence-layer churn (SwiftData
changes, future CloudKit) from ever touching the tested scoring logic.

**Ranking happens in the view layer, not via `@Query`'s sort.** `@Query` in `ContentView` fetches
by `createdAt` only; `ContentView.rankedItems` then calls `PriorityScorer.rank(_:)` on every view
evaluation and maps ranked IDs back to the fetched `TodoItemModel` objects. `@Query`'s sort
descriptors can't express the WSPT formula, the zero-time infinity guard, or the open/done split, so
this recompute-on-every-mutation approach (per `docs/overvall-plan.md`) is intentional, not a
missed optimization — scores are never stored.

**Design constraints to preserve** (for v2 CloudKit/aging support):
- `TodoItemModel` has no `@Attribute(.unique)` fields and every stored property has a literal
  default value — both are CloudKit `ModelConfiguration` requirements. Preserve this on any new
  field.
- `Importance` is backed by a plain `Int` raw value (`importanceRaw` on the model) rather than a
  native enum column, for CloudKit-friendliness.
- `PriorityScorer.rank(_:)` is a pure function over `[TodoItem]` with no external state — an aging
  term or due-date override should extend the formula here, not bolt logic onto the view layer.

**Platform-specific UI branches** use `#if os(iOS)` / `#if os(macOS)` inline within shared view
files (see `ContentView.swift`, `TodoRow.swift`, `AddTodoForm.swift`) rather than separate
per-platform view files. When adding a platform-conditional modifier, verify both `WSPTTodo_iOS`
and `WSPTTodo_macOS` build — a modifier unavailable on one platform (e.g. `.toolbar(.hidden, for:
.navigationBar)`, iOS-only) will silently pass on the other platform's build if you only test one.
